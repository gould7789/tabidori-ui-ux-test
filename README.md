# tabidori-web

타비도리 **일정 화면**(입력 → 검증 → 결과)을 실제 스택으로 옮긴 버전.
입력과 결과는 페이지 두 개가 아니라 **한 화면의 상태**다(`body[data-stage]` = `input` · `verifying` · `result`, UI/UX 설계노트 6-21절). 같은 지도와 같은 하단 카드 위에서, 검증하기를 누르면 결과가 채워진다.

- **입력**: 조건 칩(도시·날짜·출발 시각) + [검증하기](藍). 지도에는 담은 스팟의 번호 핀만, 경로선은 없음(설계노트 13-1절). 담지 않은 데모 스팟은 흐린 후보 핀 — 누르면 담기. 어드바이저 패널은 펼쳐진 채로 시작.
- **검증 연출**: 서버(`/api/verify`)가 계산한 결과를, 내 순서의 구간마다 이동수단 아이콘이 경로선을 그리며 따라가고 도착한 핀·카드에 시각과 판정이 붙는다. 건너뛰기 가능, `prefers-reduced-motion`이면 연출 없이 바로 결과.
- **결과**: 패턴 탭(내 패턴 + 위반 없는 다른 순서 최대 2개), 핀에서 체류시간·이동수단 편집, 카드 드래그로 순서 변경, [이 일정으로 확정하기](朱). "편집으로 돌아가기"는 지금 보고 있는 패턴의 순서를 그대로 입력 상태로 가져간다(개발노트 7-3).
- **색**: A안(藍 메인 · 朱 포인트 · 위반 `#8E1C3E` · 특별개관 청록 `#0F6E78`), 로고 B(`static/logo.svg`).

## 스택

| 부분 | 기술 |
|---|---|
| 서버 | FastAPI (uv로 관리) |
| 화면 | Jinja2 템플릿 + htmx 2.0.4(`static/`에 포함) |
| 지도 | Google Maps JavaScript API (AdvancedMarkerElement, Polyline) |
| 이동시간 | Google Routes API `computeRoutes` (도보·자전거·자동차) |

## 실행

```bash
cp .env.example .env      # 키 입력
uv sync
uv run uvicorn app.main:app --reload
# → http://localhost:8000
```

### 필요한 Google Cloud 설정
- **Maps JavaScript API**, **Routes API** 사용 설정
- 지금은 `GOOGLE_MAPS_API_KEY` 하나로 지도와 Routes API를 같이 쓴다. 이 키는 페이지 소스에 노출되므로 콘솔에서 **API 제한**(Maps JavaScript API·Routes API만)을 걸어둔다.
- 키에 **HTTP 리퍼러 제한**을 걸면 서버의 Routes API 호출이 거부된다. 그때는 `GOOGLE_MAPS_BROWSER_KEY`(리퍼러 제한 `http://localhost:8000/*`)와 `GOOGLE_MAPS_SERVER_KEY`(Routes API만)로 나눈다 — 값이 있으면 공용 키보다 우선한다.

### Routes API 호출과 비용
- 서버를 켤 때 추천 4곳의 6개 구간 × 3개 수단 = **최대 18회** 호출하고, 결과를 `.cache/routes.json`에 저장한다. 다음 실행부터는 캐시를 쓰므로 다시 호출하지 않는다.
- 큐레이션 목록에서 담은 스팟의 구간은 **검증하기를 누를 때 필요한 구간만** 호출한다(담은 스팟 n곳이면 최대 n(n-1)/2 구간 × 3수단). 받은 결과는 같은 캐시에 쌓인다.
- 고정값(`FALLBACK_TRAVEL`)이 없는 구간을 API 없이 계산해야 하면 직선거리로 추정한다(실측 아님, 화면에 점선·"추정"으로 표시).
- 다시 받고 싶으면 `.cache/routes.json`을 지운다. 호출을 끄려면 `.env`에 `USE_ROUTES_API=0`.
- 호출에 실패한 구간은 고정값으로 대신하고, 서버 콘솔에 `Routes API 실패 → 고정값 사용`으로 이유를 출력한다.

## 무엇이 실제로 동작하고, 무엇이 아직 데모인가

| 기능 | 상태 |
|---|---|
| 지도·핀·경로선 | **실제** (Google Maps) |
| 도보·자전거·자동차 이동시간과 경로 | **실제** (Routes API, 실패 시 고정값) |
| 일정 계산(도착·출발·종료 예상, 마감 후 도착 판정) | **실제** — 서버 `app/schedule.py` |
| 검증하기 — 내 순서 판정 + 다른 순서 패턴 계산 | **실제** — `/api/verify`. 모든 순서를 직접 계산해 위반 없는 순서를 이동시간 순으로 최대 2개. 휴무처럼 순서로 안 풀리는 스팟이 있으면 그 스팟을 뺀 순서로 계산(설계노트 18-3). 7곳 초과면 대안을 계산하지 않고 화면에 그렇게 말함. 스팟은 최대 10곳(권장 6곳) |
| 날짜 | **실제** — 기본값은 다가오는 일요일, 지난 날짜·빈 날짜는 검증 불가. 날짜가 없으면 휴무 판정을 하지 않음. 날짜를 바꾸면 카드·핀의 휴무 표시를 다시 판정 |
| 마감 시각(선택) → 총 소요시간 초과 판정 | **실제** — 비워 두면 판정 안 함 |
| 비 올 때 실외 판정 | **실제** — Open-Meteo 시간별 강수확률, 방문 시간대 70% 이상이면 위반. 16일 넘게 남은 날짜는 판정 안 함, 조회 실패 시 건너뛰고 화면에 표시(`app/weather.py`) |
| 임시휴무 확인(Loop A)과 ⏳ 표시 | **화면 흐름만 실제, 판정은 시연용** — `/api/loopa`가 1.2~4.4초 뒤 정해 둔 결과를 돌려준다(`data.loopa_demo`). 배지 6종·24시간 재사용(⚪ 제외)·검증 전 대기(90초 넘으면 ⚪)·🔴🟠 위반·🔵 공식 확인 시 휴무·마감 해제는 실제 규칙대로 |
| 시작·마감 시각·이동수단을 결과 화면에서 바꾸기 | **실제** — 바로 다시 계산. 날짜·스팟을 바꾸려면 편집으로 돌아감 |
| 순서 드래그·체류시간·이동수단 변경 후 재계산 | **실제** — `/api/schedule` 호출 |
| 검증 연출 속도 | **고정값** — 결과는 서버에서 한 번에 받고, 구간마다 0.45~0.9초로 보여준다. 실제 백엔드가 붙으면 구간 결과가 도착하는 때에 맞춰 움직이게 바꿀 것 |
| 이동수단 자동 배정 | **실제** — 도보 15분 이하면 도보, 아니면 가장 빠른 수단(실측값끼리 비교). `app/schedule.py`의 `WALK_FIRST_MAX_MIN` |
| 패턴 비교(내 패턴/A/B 독립 편집), 되돌리기, 확정 모달 | 실제 (프론트 상태) |
| 큐레이션 목록·태그 필터·휴무 숨기기 | 실제 (htmx로 서버 조각 렌더) — 데이터는 데모용 5곳. 입력 상태에서는 모달을 닫지 않고 여러 곳을 담고, 닫을 때 채팅에 한 번에 알림 |
| 자전거 이동시간 | **고정값** — Routes API가 일본 구간에 자전거 경로를 돌려주지 않음(실측: 6개 구간 모두 경로 없음) |
| 전철 이동시간 | **고정값** — Google API는 일본 대중교통 경로를 주지 않는 사례가 있어, 설계대로 NAVITIME 연결 예정 |
| 어드바이저 대화 응답 | 데모 (LangGraph Agent 미연결) |
| 담기·빼기·순서 바꾸기(입력 상태) | **실제** (프론트 상태) — 추천 4곳(지도의 흐린 핀) + 큐레이션 목록 5곳. 결과 화면에서 담으면 그 패턴 끝에 붙여 다시 검증(새 구간만 연출) |
| 휴관일 충돌 판정 | **실제** — 고른 날짜의 요일 기준(`closed_dow`). 니시키시장 일요일 휴무는 시연용 값 |
| 구간 이동시간 출처 표시 | **실제** — 이번 일정에 쓰인 구간을 세어 "실측 n · 고정값 n · 추정 n"으로 표시, 실측이 아니면 점선 |
| 큐레이션 목록 밖 스팟 추가 후 지도 반영, 확정 후 캘린더 연동 | 미구현 |
| 식당·카페 자유 검색으로 담기 | 데모 (Places 자동완성 연결 전 — 대화 안내까지만) |

데모 데이터: 교토 4곳(기온거리·야사카진자·마루야마공원·청수사), 기본 09:00 시작(예시 "기온 저녁 산책"을 누르면 16:00으로 바뀌어 청수사 마감 위반이 나온다). 청수사 마감 17:10, 니시키시장 일요일 휴무, 금각사 목요일 🔴·아라시야마 수요일 🟠은 **시연용 값**이다. 청수사 11/21~30 🔵 특별 개관은 실제 공지를 바탕으로 했지만 시각은 다시 확인할 것.

테스트용 환경변수: `OPEN_METEO_URL`(가짜 날씨 서버 주소), `LOOPA_DEMO_DELAY`(임시휴무 확인 대기 배율, 0이면 바로).

## 구조

```
app/
  main.py           # 라우트: 페이지, /api/verify, /api/schedule, /api/loopa, htmx 조각
  schedule.py       # 일정 계산·제약 판정(하드 제약 4개 + 임시휴무 확인 결과)
  weather.py        # Open-Meteo 강수확률(16일 안만)
  routes_client.py  # Routes API 호출 + 캐시 + 고정값 폴백
  data.py           # 데모 데이터
templates/
  plan.html         # 일정 화면(입력·검증·결과 공용)
  partials/         # htmx 조각 (큐레이션 그리드, 채팅)
static/             # app.css, app.js, logo.svg, htmx.min.js
```
